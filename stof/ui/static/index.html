Workflows

Record yourself performing a real multi-step flow once (login, checkout, a signup wizard) — pick it from the checklist when you start a scan and it's replayed early, extending what the crawler alone can reach.

How to record a workflow

runs on your own machine

Recording always happens on your own laptop with a small standalone script, fully offline from this server — no debug port needs to be reachable over the network, no matter where this console is deployed.

  1. Download the recorder script below.
  2. On your own machine: pip install playwright then playwright install chromium.
  3. Start a debuggable browser: google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/stof-chrome-debug &
  4. Run it: python3 record_workflow.py --output my-flow.json
  5. Walk through the real flow in that browser window — login, checkout, whatever the test case needs. Every click, fill, and page change is captured, across as many pages as the flow needs.
  6. Press Enter in the terminal to stop and save my-flow.json.
  7. Bring that file back here and click Upload a workflow above to import it.

Burp Suite Pro integrationNot set

config.json → burp

Connects to a running Burp Suite Pro instance via its REST API (Settings → Suite → REST API in Burp). Evidence capture (proxying STOF's own traffic through Burp so it shows up in Proxy history) and Active Scan (Burp's own much slower vulnerability scanner) are separate toggles on purpose — turning one on never silently turns on the other.

Out-of-band testing

config.json → burp.collaborator_url

Point this at your own OOB collaborator (Burp Collaborator, interactsh, or any equivalent host you control) to enable ssrf_tests' TC-137.6 — it sends a unique callback URL per candidate parameter; STOF doesn't poll for the callback itself, so check your collaborator's own dashboard for a hit. One collaborator serves every application, so this stays here rather than on a per-target page.
